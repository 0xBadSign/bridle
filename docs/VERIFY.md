# Verifying the README, claim by claim

One row per claim in `README.md`. Three kinds of command are used:

- `make verify` re-checks live testnet facts against public RPCs. `node scripts/verify-claims.mjs --only E09` runs one claim; the ids are in `docs/evidence/claims.json`. Needs Node only.
- `make demo-prebuilt` plays the offline story. The expected line is the `[PASS]` line text printed by `scripts/demo.mjs`. Needs Node only. Lines that mention trust, caps or `withdraw 28 USDC` come from the v3 beat and need the v3 vault wasm in `deploy/prebuilt/`.
- `cargo test -p bridle-core --test machine <name>` (or `--test golden`, `--test migration`) runs one Rust test. The expected line is `test <name> ... ok`. Needs the Rust toolchain; `make test` runs all of them.

"Where the assertion lives" gives the file and function (or the line of the `check(...)` call in `scripts/demo.mjs`).

The `cron.bridle-hq.testnet` account (it runs the public keeper cron) holds a full-access key controlled by the project owner. The "function-call keys only" claims cover the vault and arena accounts, not the cron account.
